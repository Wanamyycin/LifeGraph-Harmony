# 关系图拖动闪烁排查（2026-10-28）

## 结论与修改

当前模拟器中复现了整个图谱短暂消失、下一张画面恢复的现象。当时网页没有重新加载，没有重新收到图谱数据，SVG 节点仍存在。因此本次捕获的问题定位在 Web 画面合成/送显路径，而非业务数据变化或 D3 清空节点。

`NativeGraph.ets` 从 `RenderMode.SYNC_RENDER` 切换为 `RenderMode.ASYNC_RENDER`：让持续运动的 SVG 使用独立送显的 surface，而不是跟随 ArkUI 送显的同步 canvas。两种模式的含义已核对当前 SDK 的 `ets/component/web.d.ts`。

保留此前的 `onInactive()` / `onActive()` 可见性管理，正常返回时不刷新页面；加载失败、渲染器退出及切换主题的恢复路径不变。主页和人物关系图共用该组件，修改同时作用于两处。

不修改数据、布局算法、关系强度、筛选条件、配色或缩放按钮。临时 Web 调试开关和诊断日志已从产品源码移除。

## 对照实验

设备为当前连接的 DevEco 模拟器，分辨率 1280×2832。使用既有的 2 节点主页和 3 节点人物图谱，不新增或修改人物、关系、事件。

连续触摸拖动由设备上实际 ArkWeb 调试通道注入：一次按住、约 240 次无规则位置移动、松手。每轮通过 `snapshot_display` 采集 50 张系统屏幕截图，包含 ArkUI 及 Web 实际显示。诊断期间同时记录网页重画、消息、DOM 清空与节点数量。

| 方案/场景 | 屏幕采样 | 图谱空白 | 黑框 |
| --- | ---: | ---: | ---: |
| 原同步渲染，主页拖动 | 50 | 1 | 0 |
| 同步渲染 + SVG 合成层 CSS，主页拖动 | 50 | 14 | 0 |
| 异步渲染，主页拖动 | 50 | 0 | 0 |
| 异步渲染，人物关系图拖动 | 50 | 0 | 0 |
| 异步渲染，系统输入链路的 16 次平移手势 | 50 | 0 | 0 |
| 无诊断代码的最终版，深色模式下 16 次系统平移手势 | 50 | 0 | 0 |

连续节点拖动对照中，拖动期间的 render 次数、图谱消息数、DOM 清空次数均为 0，节点数恒定。SVG 合成层 CSS 的对照效果更差，已放弃，没有加入正式资源。

异步渲染额外回测了 5 次后台返回、3 次从人物详情返回图谱、1 次放大后后台返回。9 次均未出现黑框；隔离力导布局自然运动后，比对返回前后节点 transform 和缩放 transform，均保留。随后从人物图谱逐级返回主页，也正常显示。

## 验证边界与复现资料

修复版累计采样 200 张，均未捕获图谱空白或黑框；深色模式验证后已恢复用户原来的跟随系统设置。最终源码构建成功，8 个测试脚本共 107 项通过，且已重新安装不带诊断开关的最终版本。

这些是有限的屏幕采样，并非逐帧录像，不能据此保证所有过渡帧、所有机型均无闪烁。更多节点、事件封面/头像、其余配色主题及真机仍需视觉验收。
