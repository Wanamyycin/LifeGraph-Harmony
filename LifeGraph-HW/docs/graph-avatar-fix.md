# 图谱头像不显示排查（2026-10-28）

## 原因

用户反馈的范围是：人物列表能显示已保存的头像，关系图里没有头像。

`9ed99dc`（离线上架适配）给 `NativeGraph.ets` 增加了 `onlineImageAccess(false)`。当前模拟器的 ArkWeb 中，这个开关也使内嵌的 `data:image/jpeg;base64,...` 图片一直处于等待加载状态。原生人物列表直接读取本地文件，不经过该 Web 设置，因此仍能显示。

本轮用应用自带图片执行真实 `MediaFiles.thumbnail()`，成功生成 96×96 JPEG 的 data URI；未出现原生解码、压缩或编码错误。相同 URI 在网页侧的对照结果如下：

| 设置 | 原生缩略图 | 网页 Image.decode |
| --- | --- | --- |
| blockNetwork=true，onlineImageAccess=false | 正常 | 3 秒超时，naturalWidth=0 |
| 上述设置 + imageAccess=true | 正常 | 仍然超时 |
| blockNetwork=true，onlineImageAccess=true，imageAccess=true | 正常 | 成功，96×96 |

因此本次问题定位于该 Web 开关，与节点结构调整、加减号图标或头像保存数据无关。`MediaFiles.ets` 的头像转换和 `NativeApp.ets` 的缩略图准备代码仍与早期提交 `794e733` 一致。

## 修复与离线边界

允许 Web 加载图片，同时保持 `blockNetwork(true)`、`fileAccess(false)`、`MixedMode.None`。应用清单继续不申请 INTERNET 权限，也没有恢复 AI 服务配置或原生网络客户端。图谱只接收原生侧编码后的本地头像缩略图和事件封面，不把用户图片路径改为网络地址。

本次头像修复不改变图谱的渲染模式或页面可见性恢复逻辑。

## 验证

- 新建了有独立标记的临时测试人物，使用正常的数据服务注册图片、保存头像和与“我”的关系，再走正常快照及缩略图准备流程。
- 模拟器中，人物列表、人物详情、主页关系图、该人物自己的关系图均能显示头像。
- 安装不带诊断代码的最终版本并重启应用后，已保存头像仍在主页及详情显示。随后通过应用正常删除流程清理本轮临时测试人物；数据库查询确认临时人物及其媒体记录均已清空，原有人物没有修改。
- 增加图数据回归：主页、人物和生活图谱保留本地内嵌头像及事件封面；没有可用缩略图时保留空值回退。
- 离线发布检查改为同时要求“允许图片加载”和“总体网络拦截”，防止再次用禁用图片的方式维持离线。
- 最终版本构建成功，8 个脚本共 108 项测试通过。

专项诊断、测试图片写入和临时人物自动创建代码均未保留在产品源码中。测试截图、实验基线和脚本在工作区的 `experiments/graph-avatar` 与 `experiments/desktop-card/evidence/avatar-*` 下，不进入安装包。

本轮验证基于当前 DevEco 模拟器；真机及用户具体原始照片仍需最终验收。
