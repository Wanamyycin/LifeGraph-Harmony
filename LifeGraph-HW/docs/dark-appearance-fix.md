# 深色适配修复

2026-10-26。根据用户截图检查主页图谱浅色框及助手输入提示文字过暗的问题。

## 原因与修改

- 图谱通过背景色是否等于旧值 `#201E1B` 判断明暗。上一轮背景更换后，该判断恒为浅色。现与原生 Palette 共用外观判断，按浅色、深色或跟随系统选择 HTML，不再依赖具体颜色值。
- 页面显式绘制了深色背景，但应用的原生控件仍跟随系统。当系统浅色、应用手动深色时，默认提示和系统弹窗可能使用浅色资源。现同步当前应用的 ColorMode；选择跟随系统会解除应用覆盖，不更改系统设置。
- NativeApp 与 AI 设置弹窗中的 TextInput、TextArea、Search 显式设置提示色、光标／搜索图标色。关系选择器设置普通选项、选中项、文字和背景色。
- 增加 onPrimary／onDanger，修正深色主题中浅色按钮背景配白字的问题，覆盖保存、新建、已选标签、录音及播放等控件。无输入时发送按钮仍保持禁用状态。
- 原生 ColorMode 更新去重，防止配置回调反复调用；设置失败不记作已应用，允许后续重试。窗口销毁时解除外观回调。

## 验证

新增回归先复现 `forest-light` 错选，再修复通过。四个主题分别覆盖手动浅色、手动深色、跟随系统及系统明暗组合，并验证所选 HTML 背景与 Palette 相同；覆盖原生模式切换／失败重试，以及深色主操作文字对比度。本地六组共 98 项通过（11＋19＋16＋10＋29＋13）。

在运行中的 DevEco 模拟器覆盖安装本轮 HAP，实际确认：

- 首页加载 `forest-dark.html`，图谱白框消失，文字与缩放操作可见。
- 助手输入提示为浅色；没有发送新问题。
- 系统日期选择器、关系下拉菜单、清空聊天确认框为深色，文字可读。
- 手动浅色 → 深色 → 跟随系统（当前系统浅色）→ 深色切换正常，最后恢复原有森林／深色。
- 人物草稿与清空聊天操作均取消；没有新增人物／事件或清空聊天。
