# 桌面关系微图设计

版本：1.0.0　｜　代码基线：`0cba655`

## 1. 功能目标

桌面入口用于快速查看重要人物的关系轮廓和新建事件。卡片不替代完整关系图；为控制占屏面积，最终提供2×2尺寸，在有限空间内保留人物短标签、关系线和记录入口。

## 2. 配置与展示

| 项目 | 实现 |
| --- | --- |
| 名称与尺寸 | 关系微图，`RelationshipCard`，2×2 |
| 人物范围 | 中心“我”及最多六位活跃人物，不重复选择 |
| 配置入口 | “我的→桌面关系卡片”或卡片右上角设置入口 |
| 名称策略 | 默认隐藏，以序号表示；可选名字首字、记录中的称呼 |
| 关系线 | 仅投影卡片中已有关系；同一人物对合并绘制，取最大线宽 |
| 配置作用域 | 所有卡片共用同一套人物与展示设置 |
| 刷新 | 应用发布数据时更新运行卡片；系统按配置调度更新 |

节点圆点展示短标签；“记录中的称呼”模式最多取前两字作为圆点文字，辅助功能标签可保留前八个字符。选择隐藏姓名不代表关系结构匿名化，人物数量、连线和用户对照记忆仍可能透露信息。

## 3. 数据流

`DesktopCardStore`使用独立Preferences保存配置及展示缓存。跨进程读取前移除Preferences内存缓存，再获取已落盘内容；写入操作串行执行，先保存并flush，再查询系统拥有的运行卡片ID并逐个更新。

配置保存成功与系统刷新成功分别处理。没有运行卡片时仍可保存；部分刷新失败时明确报告“已保存，部分卡片刷新失败”，不把业务保存结果倒退为未保存。

## 4. 内容边界

卡片界面没有照片、头像、录音、事件正文及地点。投影模型保留共同事件数量和最近记录摘要字段；共同记录计算要求“我”和选中人物同时参与，当前紧凑卡片页面不渲染这些事件明细。`showEventTitles`默认关闭，当前设置页不提供开启控件。

卡片配置不在ZIP备份表中。恢复业务备份后，如果人物ID不再有效，需要重新选择。卡片可能暂存旧展示，应以应用内记录为准。

## 5. 跳转与保护

卡片使用系统router动作唤起`EntryAbility`。点击人物进入人物详情，点击中心或设置图标进入卡片设置，底部按钮新建事件。启动参数只接受预定义动作，并限制人物ID长度。

应用初始化后处理暂存动作。事件/人物/资料编辑、分类与外观设置、录音或数据变更期间延后跳转，避免覆盖草稿。当前只保留一个待处理请求，新请求可替代此前请求，不承诺请求队列。

## 6. 验证范围

`test-desktop-card.cjs`覆盖13项数据投影、缓存与刷新失败隔离、参数和导航保护测试。已有模拟器记录覆盖添加、配置、人物跳转和快速记录；不据此认定所有真机、多实例、系统重启和大字号均已验收。
