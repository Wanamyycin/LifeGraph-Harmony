# 图谱头像加载兼容性案例

修复提交：`269733d`　｜　实验日期：2026-10-28

## 1. 现象

同一位人物在原生列表中显示头像，关系图仍显示纯色圆球。人物记录和头像引用已经保存，因此排查需区分原生媒体处理与Web图片解码。

## 2. 对照结果

原生`MediaFiles.thumbnail()`生成96×96 JPEG data URI。同一URI在图谱Web环境中的解码结果为：

| Web设置 | 原生缩略图 | 网页解码 |
| --- | --- | --- |
| 总体网络拦截，关闭onlineImageAccess | 正常 | 3秒超时，naturalWidth为0 |
| 上述设置，同时开启imageAccess | 正常 | 仍然超时 |
| 总体网络拦截，开启两项图片能力 | 正常 | 成功，96×96 |

当前实验环境中的`onlineImageAccess(false)`同时阻断了内嵌图片，原生列表直接读沙箱文件而不受该设置影响。此前离线适配提交`9ed99dc`引入了这一配置。

## 3. 修复与边界

图谱保留`blockNetwork(true)`、`fileAccess(false)`和`MixedMode.None`，开启`onlineImageAccess(true)`、`imageAccess(true)`。应用仍不声明INTERNET，不恢复网络客户端。图谱只接收原生编码的缩略图及事件封面。

原生缩略图算法、人物保存和关系数据结构没有因本次修复改变；Web渲染模式及可见性恢复另行处理。

## 4. 验证

模拟器使用临时测试人物及应用自带图片走正常媒体登记、头像保存和快照流程。列表、详情、主页图谱及人物图谱均显示头像，重启后保持。测试完成通过正常删除流程清理临时人物和媒体。

图数据回归检查主页、人物和生活图中的内嵌头像及封面；离线检查同时约束图片能力与总体网络拦截，避免再次通过禁用图片实现离线。实验基于DevEco模拟器，不覆盖所有真机图片格式和超大图片。
