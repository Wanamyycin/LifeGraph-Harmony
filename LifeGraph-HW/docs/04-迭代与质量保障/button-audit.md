# 按钮与状态反馈修复

## 1. 问题与定位

事件编辑中的参与者、生活分支和情绪按钮可以触发数据变化，但部分选中外观没有更新。关系强度也出现写入值正确而显示值不随动的情况。问题涉及状态依赖和列表复用，不能通过“保存成功”的提示确认界面正确。

旧通用Builder将选中状态作为普通参数传入。在以稳定ID复用的ForEach中，部分生成的更新函数持有初始状态，没有建立预期的响应式依赖。关系行若按位置而非身份关联，也可能导致显示目标与提交目标不一致。

## 2. 修复设计

| 组件 | 处理 |
| --- | --- |
| ChoiceChip | 显式传入选中状态与回调，覆盖参与者、分支、情绪及主题等选项 |
| ActionButton | 将保存状态和动态文案作为组件属性，统一禁用和重复提交控制 |
| RelationEditorItem / Row | 可观察的关系对象、ObjectLink和稳定行ID；目标以人物ID保存 |
| EventAttachments | 父附件列表变化触发更新，封面和移除回调读取最新对象 |
| 列表行 | 名称或更新时间进入必要的复用键，避免编辑后复用旧显示 |

这些调整保留真实数据库、选择器与麦克风调用，不以界面模拟成功替代业务写入。

## 3. 验证方法与范围

历史模拟器专项检查覆盖关系目标、强度及事件多选；当前宿主测试覆盖保存校验、数据关联和失败回滚。两类证据分别保存：宿主通过不代表设备触摸状态均已验证。

回归按“点选→显示→保存→重开”检查同一字段；多行关系增加删除首行后继续编辑的场景。动态按钮应在保存中禁用，失败时恢复可操作并显示原因。
