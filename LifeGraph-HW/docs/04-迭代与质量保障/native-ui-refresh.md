# 界面与交互设计

## 1. 信息层级

Life Graph以关系图作为首页中心，同时保留记录列表、人物列表和搜索。图谱适合观察联系，列表与表单承担精确查找和录入，避免将全部任务压在图形操作上。

底栏固定为图谱、记录、加号、人物、我的。加号突出新建事件这一高频动作；“我的”使用齿轮，与相邻的人物图标区分。首页、人物和记录页移除重复进入个人页面的右上角菜单，搜索保持可见。

## 2. 视觉语言

页面使用留白、圆形人物节点、柔和背景和有限的主题色。人物与事件通过图形、文字和连线形成层次；界面文字保持生活记录语境。关系强度是用户自己的标记，界面不以自动结论替代用户判断。

统一Palette连接原生页面与Web图谱，支持四套主题及深浅色。缩放控件采用相同尺寸的几何线条，避免字体中的加号与减号产生视觉大小差异。

## 3. 录入与反馈

人物编辑保留头像、描述及多行人物关系；事件编辑保留时间、参与者、生活分支、情绪、地点、图片和音频。选项使用显式选中状态，保存过程限制重复操作，校验失败就近提示。

新事件默认选中“我”，允许取消；分支和情绪可多选，也可不填。人物、事件与分类分别编辑，减少误删关联对象的风险。彻底删除、覆盖恢复等操作在执行前确认。

## 4. 手势与边界

原生Scroll/List及横向筛选条使用Spring边缘反馈，短内容也启用反馈。图谱独立处理节点拖动、平移与缩放，绘制内容在Web画布边界裁剪；原生回弹配置没有改变这套图谱手势。

图谱普通返回不整页重载，连续拖动使用异步渲染。当前没有节点越界吸附，也没有全部设备的帧率与手势协调测量，渲染与恢复的定位证据见[图谱渲染稳定性案例](graph-flicker-investigation.md)。

## 5. 桌面入口

关系微图采用2×2尺寸，最多展示六位人物及中心节点。默认隐藏称呼，通过人物和快速记录入口连接完整应用。卡片不复制首页全部交互，也不在桌面展示事件正文或媒体，控制占屏面积和旁观可见内容。
