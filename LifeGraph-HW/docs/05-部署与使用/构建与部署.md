# 构建与部署

版本：1.0.0　｜　代码基线：`0cba655`

## 1. 工程环境

在DevEco Studio打开仓库的`LifeGraph-HW`目录，完成依赖Sync，选择`entry`模块。工程使用ArkTS、ArkUI、ArkData、ArkWeb及FormKit；目标SDK为HarmonyOS 26.0.0，最低兼容声明为6.1.0（API 23）。本地Web资源随应用分发，运行图谱不需要从网络下载D3。

| 配置 | 值 |
| --- | --- |
| Bundle | `com.njulifegraph.lifegraph` |
| 版本 | `1.0.0` |
| 主Ability | `EntryAbility` |
| 卡片 | `RelationshipCard`，2×2 |
| 业务数据 | 应用私有RDB与媒体目录 |

源码工程与本机签名环境分别管理。签名证书、私钥、口令和发布账号不属于公开交付内容；在新的电脑上应使用有权限的签名身份重新配置，不能假设仓库自带可用证书。

## 2. 构建

工程脚本复用已安装的DevEco工具及依赖缓存，不自动安装SDK。在工程目录执行：

```powershell
./scripts/build-local.ps1
./scripts/build-local.ps1 -Target ohosTest
./scripts/build-local.ps1 -BuildMode release -AppPack
```

默认工具路径为`F:/DevEco Studio`，其他安装位置通过`-StudioHome`指定。没有匹配缓存时先在DevEco完成Sync。`ohosTest`命令仅构建测试模块，不表示已经执行设备测试。

| 产物 | 目录 |
| --- | --- |
| HAP | `entry/build/default/outputs/default/` |
| APP | `build/outputs/default/` |
| 构建输出记录 | `evidence/build-*.log` |

目录中可能同时存在signed和unsigned产物。不同构建模式可复用中间目录，取包时核对生成时间、内嵌`debug`标记、包名和版本，不能只依据文件名判断。正式软件包的平台检测结果见[上架与平台检测结果](../04-迭代与质量保障/上架与平台检测结果.md)。

## 3. 安装与启动

在DevEco启动匹配SDK的模拟器，或连接受支持的真机，使用IDE运行`entry`。命令行安装应选择该设备接受的签名HAP：

```powershell
hdc list targets
hdc install <signed-hap-path>
hdc shell aa start -b com.njulifegraph.lifegraph -a EntryAbility
```

连接多台设备时先指定目标，安装后核对当前运行的包身份。旧试验包是不同应用，安装新包不会自动迁移其数据。卸载可能移除应用私有数据，已有记录应先导出备份；不要把卸载当成普通升级步骤。
