## 替换决定

- Expo Router／Hooks／React Query 改为 ArkUI Navigation 与本地状态；业务服务独立于页面，不继续依赖 React 运行时。
- Drizzle／Expo SQLite 改为原生 RDB 参数化 SQL，事务中的操作统一使用 Transaction 对象。设备测试已执行实际建库和回滚，不只是主机模拟。
- Expo 文件与媒体库改为系统选择器、沙箱文件、AVRecorder／AVPlayer；用户选中的临时 URI 不作为永久路径保存。
- RN WebView 改为 ArkWeb；D3 是离线绘图实现，不能称为纯原生绘图。原生侧只接收限定消息，页面离开后失效。
- JSZip 改为独立流式 ZIP32 存储格式，按 64KB 分块读写并做 CRC；图片／音频原本已压缩。导入仅接受鸿蒙版自有格式，当前总计 1GB、单附件 512MB、清单 16MB。
- 原方案曾提出恢复到新数据库后切换；本轮采用先复制媒体到唯一新文件名，再在同一 SQLite 事务内校验并替换所有表，失败回滚并删除新复制文件。旧媒体不会在提交前覆盖，后续启动清理旧文件。仍需故障／断电实测。
- 文件复制失败删除当前导入文件；注册媒体失败补偿文件；录音临时文件导入后清理。异常退出遗留的未引用媒体在下次启动清理，取消表单仅清理此次未引用附件。
- SDK 文件读写 offset 相对于当前位置，适配器改为 lseek 绝对定位，再循环处理部分读写；实际适配器注入相同语义的主机替身已通过测试，原生 ZIP 往返仍待测。

## 后续执行顺序

1. 先固定一条验收流程：创建人物与关系 → 创建含图片／语音的事件 → 搜索／筛选／图谱进入详情 → 编辑 → 强制停止重开 → 备份恢复 → 两种删除。每步记录实际结果。
2. 先关闭会丢数据、误删、无法启动的阻断缺陷；普通外观问题记录后集中处理。用户未给细节的 bug 不假定已修复。
3. 用独立测试数据测量 50／200／500 节点的首屏、拖动、缩放、内存与前后台恢复，不向用户当前数据库灌入演示记录。尚未给出“流畅达标”的结论。
4. 验收已补齐的空间占用统计，逐屏校准原应用布局，集中核对键盘、系统安全区、大字体、深色模式、长内容与返回动作。
5. 完成媒体／备份原生流程及真实 AI 联调，再进行设备重启和发布签名准备。正式 bundleName、真机／发行签名和商店发布单列。
