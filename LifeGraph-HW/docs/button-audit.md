# 按钮与选中反馈检查

日期：2026-10-21 至 22。用户授权修复 bug3 并全面检查按钮失灵，生产入口为 NativeApp；旧人物试验的 PeoplePage 仅作历史预览参考，不作为当前生产入口验收。

## 原因与修改范围

旧 chip(label, selected, action) 将 selected 作为普通值传给 @Builder。在按稳定数据 ID 复用的 ForEach 中，Button 的更新函数只捕获初始布尔值，页面数组虽变化，选中显示并未建立对应的状态依赖。截图和 SDK 生成的代码均可见此问题。

- 21 处点选／导航调用改为 ChoiceChip，直接绑定父状态及回调。覆盖事件三个多选组、事件分支筛选、两类图谱筛选、搜索分类、主题／明暗选项及详情导航。
- 8 处主要操作改为 ActionButton，避免保存中等动态文案仍用初始值。保留保存期间禁用、错误反馈与防重复提交。
- 页面标题改为 PageHeading，底部标签切换后标题与搜索入口同步；返回／新建／缩放图标去除裁切用的多余内边距。
- 附件列表改为 EventAttachments，父附件数组变更能更新展示，封面和移除回调读取最新数组；普通业务路径未改变。
- 分类行 key 加名称，防止改名写入成功后旧行仍显示旧名称；搜索事件行 key 加更新时间，防止编辑后结果卡片复用旧数据。
- AI 空问题发送按钮明确禁用，避免点击后静默返回。日期、分类保存、录音、文件选择等仍走真实 API，未以假成功代替。

其余 Builder 已检查：field／empty／menu 的参数是当前用途下的静态文本或稳定目标 ID；personDetail／eventDetail／graphPage 的 ID 在页面生命周期内稳定，状态读取在原生更新块内。关系行继续使用上轮已验证的 @Observed／@ObjectLink 与稳定行 ID。

## 本轮收尾结果

最新产品代码构建成功，34 项主机回归通过。实际设备检查分阶段累计观察到 23 个不同检查点通过：核心事件／导航 14、分类管理 3、外观与分支图 5、AI 发送状态 1。其中外观阶段独立完整执行通过；整个按钮脚本没有完整通过，不能用累计检查点代替全套验收。

备份导出取消后的提示检查未通过断言，界面证据只显示正常备份页，尚不能确认是应用问题还是选择器／脚本时序问题。进一步隔离检查因自动审批服务用量限制未执行；这是审批服务失败，不是安全性否决。2026-10-22 用户关闭模拟器并明确无需继续实机测，因此停止设备检查，保留该项待确认，不启动模拟器重试。

核心测试事件及三类临时分类已通过应用操作清理，外观已恢复；保留用户现有人物与关系。新补充的 test-button-extras-ui.py 尚未执行，日期选择、录音反馈、其余列表筛选不计为通过。截图和摘要是分阶段证据，部分历史摘要 completed=false，不能据此声称整套脚本成功。
